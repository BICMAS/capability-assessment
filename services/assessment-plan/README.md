The assessment-plan service stores role assignments against a published framework version, and the assessment plan for each assignment. An admin assigns people to one role on one published version. The service reads that version from capability-framework and the person from the directory. It stores the version id and role id, and publishes assessment.assigned. It does not change the directory role title.

An assignment records the person, the published framework version, one role in that version, who assigned it, when, a status of assigned, and an optional exception reason. A plan belongs to one assignment. It has a version number and a status of draft, generated, under_review, changes_requested, or approved. Each plan skill is one role-capability requirement and stores the recommended method, a short rationale, instructions, assessment items, and a rubric. An admin generates version 1 by asking the model for instructions, assessment items, and rubric anchors. The method is chosen in code and sent as a fixed constraint. The plan stores the prompt version and model name. The provider key is read from ASSESSMENT_MODEL_API_KEY. A missing key or an invalid draft does not save a plan. An admin can edit a generated or changes-requested skill, submit the plan, request changes, or approve it. Approval publishes assessment.plan_approved and creates one session for the person on the assignment. A session is not created from an unapproved plan. Its status moves from assigned to started to submitted, and it stores the employee’s written answer for each item. An approved plan cannot be edited. The next change is a new draft version copied from the approved plan.

The capability-framework service owns frameworks, immutable published versions, roles, capabilities, proficiency levels, behavioural indicators, and role requirements. A published version is not updated; editing it inserts the next draft. An admin CSV import is stored in the local bucket, checked for duplicate capability codes and missing required levels, and cannot move to review while a proposal is pending. Publishing a version freezes it and emits framework.published.

It also owns role skills profiles. A profile is a versioned set of required skills for one role identity in the caller's organisation. Profile statuses are `profile_draft`, `profile_in_review`, and `profile_published`. They are separate from framework statuses. A published profile version is immutable; the next change inserts a new draft and keeps the published skills unchanged. Canonical skills and role identities are referenced by id and are not copies of organisation or person records.

Clarification and generation stay in this service. Missing critical context produces saved questions before any model call. Generation is a queued job: the HTTP request returns after the job is stored, and a worker calls the provider through `roleprofile.Provider`. `ROLE_PROFILE_MODEL_API_KEY`, `ROLE_PROFILE_MODEL_NAME`, and `ROLE_PROFILE_MODEL_URL` are read by the server process. A generated result is stored as an editable draft with its model, prompt version, and input hash. It is not submitted or published automatically. Later HR edits keep that generated snapshot.
